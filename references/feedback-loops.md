# 反馈回路搭建目录（辨征问展开卷）

> 配合 `对鸟Deducere` 使用。正文只保留「先有一条能对**这个** bug 变红的命令」硬闸；本卷给各接缝的构造顺序、收紧方向与降级路径。

## 目录

§一 十种接缝（按顺序试）｜§二 收紧回路｜§三 非确定 bug｜§四 真建不出回路｜§五 完成判据

## 一、十种接缝（按顺序试）

在能触到 bug 的最浅接缝建回路，从可自动复现到要人介入逐级下沉：

1. **失败测试**：单元／集成／端到端，哪层够得着 bug 就用哪层。
2. **HTTP 脚本**：对运行中的开发服务发请求，比对响应。
3. **CLI 调用**：喂固定夹具输入，stdout 对已知良好快照 diff。
4. **无头浏览器脚本**：驱动 UI，断言 DOM／console／网络。
5. **回放已抓 trace**：把真实请求／载荷／事件日志存盘，隔离回放进代码路径。
6. **一次性 harness**：起最小子集（单服务、mock 依赖），一次函数调用走到 bug 路径。
7. **属性／fuzz 回路**：「有时输出错」类，跑批量随机输入找失败模式。
8. **二分 harness**：bug 出现在两个已知状态之间，自动化「起 X 状态、检查、重复」，可接 `git bisect run`。
9. **差分回路**：同一输入过旧版 vs 新版（或两套配置），diff 输出。
10. **人工介入脚本**：最后手段。必须人点时，用 `scripts/human-loop.template.sh` 把人也结构化进回路；采集到的输出再喂回给 agent 的四问三账。

**抽象交互层接缝**：UI／移动端／桌面交互类 bug，先判断能否在更底层接缝复现（组件调用、事件回放、状态快照）；只有底层接缝够不着时才上交互层脚本。⛔ 不把某一宿主的具体浏览器、视口尺寸、端口写进通用流程——那是当次任务的耦合。

**报错类型 → 首选接缝**（只给首选入口，根因另判）：

- 语法／类型错 → 失败测试。
- 连接拒绝 → HTTP 脚本／CLI 调用。
- 超时／等待类 → 条件等待＋计时回路。
- 断言失败 → 差分回路。
- 无报错但结果错 → 属性／fuzz 回路。

**性能与时序接缝**：

- 性能回归：用既有基准脚本，修复前后跑**同一命令**，取 rc＋耗时对比；性能红判据挂 T11，本件不写毫秒／百分比数字。
- 时序／并发：加压、并行、收窄时序窗、注入等待（接 §三）；竞态类用固定随机种子＋受控并发复现，⛔ 靠加大超时掩盖。

## 二、收紧回路

有了**一条**回路后，把它当产品收紧：

- **更快**：缓存 setup、跳过无关初始化、收窄测试范围。
- **信号更锐**：断言具体症状，不是「没崩」。
- **更确定**：钉时间、固定随机种子、隔离文件系统、冻结网络。

一条 30 秒的 flaky 回路不比没有强多少；2 秒确定性回路才是调试杠杆。

## 三、非确定 bug

目标不是干净复现，而是**提高复现率**：连触发 100 次、并行、加压、收窄时序窗、注入等待。50% 复现率可调试；1% 不可调试，先把复现率抬到可调试区间。
- **彻底不可复现时**：只收边界与诊断（触发条件、已排除项、证据级），⛔ 硬修；等采集件到位再开回路。

## 四、真建不出回路

明确停下并说清：列已试过的路径，向用户要 (a) 能复现的环境访问权，(b) 脱敏采集件（HAR／日志转储／core dump／带时间戳录屏），或 (c) 临时加生产侧插桩的许可。⛔ 没有回路就进入假设阶段。

## 五、完成判据（判据见判据表 J1–J4）

本卷不复写判据句：辨征问出口的四种状态（能变红／确定／快／agent 可跑）及其「判违规的样子」在 `判据表.md` J1–J4。本卷只补机制侧两点：

- **「能变红」的定义**：走到真实 bug 代码路径、断言用户的确切症状、修后能转绿；「不报错」不算。
- **机锁用法**：`scripts/verify_red_green.py --expect red --cmd "<命令>" --match "<症状正则>"`——非零退出码且命中症状才算故障锁定；命令竟返回 0，判假复现。
