## 一、反例先行

性能工作最容易在四处滑走，四条纪律各挡一处：

- 冷缓存的基线比热缓存的结果 → 量的是缓存，不是改动（纪律一挡）；
- 一次改三处，只出一个数 → 说不清哪处起作用（纪律二挡）；
- 「没变慢」就留下 → 复杂度白背一辈子（纪律三挡）；
- 试过的死方案没记账，下季度再试一遍（纪律四挡）。

## 二、四条纪律

每条给：机制（为什么）／候选判据问法（我这次算不算违规）／判违规的样子／症状句。四条都是 T11 候选口径，不是正式 J 判据。

### 纪律一 · 同条件基线（对应辨征问）

- **机制**：基线与复测须同命令、同环境、同缓存条件、同负载；多次取样，报波动带（中位数＋区间），不比单次均值。冷缓存基线配热缓存结果，量的是缓存。
- **候选判据问法**：我的基线与复测，命令／环境／缓存／负载四项是否逐项相同？波动带报出来了没有？
- **判违规**：只报一次均值；冷／热缓存混比；换命令或换输入后说「变快了」。
- **症状句**：「改完快了不少」（问不出同条件数字）。

### 纪律二 · 单变量定位（对应循链问）

- **机制**：用 profile 找瓶颈第一次出生处（主线程长任务、DOM 更新、轮询分配、Canvas 帧成本、字体与图片加载等），一次只改一个变量。三处一起改出一个数，无法归因。
- **候选判据问法**：本次改动涉及几个性能变量？能否指着 profile 说清瓶颈出生在哪一行？
- **判违规**：一次提交三个优化；没 profile 就猜瓶颈；凭「感觉这里慢」改。
- **症状句**：「我把这几处都优化了一下」。

### 纪律三 · 越波动才算赢（对应验真问）

- **机制**：收益要越过运行波动才算数；退步、功能测试变红、落在噪声内的「没变慢」，一律回退。正确性闸门指标——测试红着的「优化」是回归不是赢。
- **候选判据问法**：收益是否越过波动带？功能测试是否仍绿？落在噪声内我回退了没有？
- **判违规**：3% 收益落在 ±5% 波动里还留着；测试红了说「性能赢了」；把「没变慢」当保留理由。
- **症状句**：「至少没变慢吧」。

### 纪律四 · 记账防重（对应净痕问）

- **机制**：保留与回退都记一笔——基线 → 结果 → 波动 → 结论。回退的改动不留 git 痕迹，不记账下季度必然重试。记的是具体实验，不是通用预算。
- **候选判据问法**：这次实验（不论去留）有没有落到账上？下一个调试者能不能读到「这条试过、结论是什么」？
- **判违规**：回退了就当没发生过；只记成功不记失败；账里没有基线和波动。
- **症状句**：「这个方案好像试过，但找不到记录了」。

## 三、接进四问三账

- **辨征问**：性能回归先要一条能对**这个**症状变红的基线命令（J1／J2），基线即「能变红的性能量」。没有具体症状和实测基线，不进后三问。
- **循链问**：profile 是循链的证据，瓶颈出生处要落到 `path:line`（J12）；猜测降为假设（J10）。
- **验真问**：同条件复测是「同一命令先红后绿」的性能版（J17）；回退纪律是验真的出口——不越波动即不绿。
- **净痕问**：记账并入过程账四段式（J26），⛔ 另立「性能账本」；回归入口与监控归防再犯三选一（J20）。
- **结果账**：性能收益要隔期、换宿主仍成立才算 L2；本会话的同条件复测只到 L1，⛔ 写「已优化完成」。

## 四、边界与转正

- 本卷四条是**测量纪律**，不是通用优化方法论；固定预算（包体积／字体总量／核心网页指标阈值）留独立技能作参考，⛔ 直接变成对鸟硬判据。
- 无具体症状、无实测基线，不谈优化（对鸟非目标：不做库级巡检与批量优化）。
- 四条仍挂 T11 候选，⛔ 当正式 J 判据引用；真实性能 bug ≥2 次实测后，按对鸟规矩（判据先跑过 ≥2 次再入正文）决定是否转正进判据表。转正时删本卷候选问法、只留机制，判据句进判据表。
- 未实测的毫秒数／百分比⛔ 写进本卷当阈值。
