# 汇报、清理与交接卷（净痕问展开）

> 配合 `对鸟Deducere` 使用。正文只留「收尾逐项核对、汇报按段写」；本卷给模板、清理清单与交接对接。

## 目录

§一 结构化汇报模板｜§二 收尾清理清单｜§三 回滚点占位（Y1）｜§四 逐项验证（Y5）｜§五 交接对接

## 一、结构化汇报模板

修复汇报按段写：

- **根因**：一句话说清。
- **因果链**：触发条件 → `path:line` → … → 用户看到的现象。
- **引入时间**：引入问题的提交（查过历史时）。
- **个例还是普遍**：普遍问题列出排查到的位置和处理结果。
- **改了什么**：修复位置，以及为什么改在这里。
- **验证**：修复前失败、修复后通过的同一用例／命令。
- **防再犯**：回归测试，以及提议的自动检查或审查重点。
- **没验证的部分**：单列（如打包后的环境）。

多项修复先列**逐症状红绿链**，再写八段汇报；总 `N/N` 只作汇总，⛔ 替代逐项证据：

| 症状 | 红命令 | 绿命令 | 接缝 | 证据级 | 结果账 |
|---|---|---|---|---|---|
| 用户可见的确切症状 | 修复前同命令＋rc＋症状命中 | 修复后同命令＋rc | 真值／结构／表现／服务端到端 | L0/L1/L2 | 待隔期／已复验 |

- 修复后补写的测试标 **「后补回归」**，⛔ 倒填成「先红后绿」。
- mock 只标 **「调用通过」**；真实浏览器打开、服务换码、消息投递等外部效果另列实测证据。
- 某一项没有红命令或接缝只到 mock，就在表内写明，⛔ 用其他项的绿灯遮过去。

⛔ 未复现的候选修复不得套成「已修好」（判据 J23）。

## 二、收尾清理清单

宣布完成前逐项核对：

- [ ] 原回路不再复现（重跑辨征问回路）。
- [ ] 回归测试通过（或无正确接缝已记录）。
- [ ] 所有 `[DEBUG-...]` 插桩移除（按前缀 `grep` 干净）。
- [ ] 一次性原型删除（或移到明确标注的调试位置）。
- [ ] 临时脚本、测试数据已还原；占用的端口／服务已释放。
- [ ] 正确假设写进 commit／PR 说明，供下一个调试者学习。
- [ ] 本次可回写 P 池的观测已记录：假设条数、探针次数、止损是否触发、是否升档（无则记「无」）；有实测观察回写 `pending-thresholds.md` 流程实测记录。

插桩与临时文件从循链问起就在清单上登记（文件/前缀/用途），收尾逐项销账；⛔ 靠收尾手工考古。

## 三、回滚点占位（Y1）

- 已在 Git 版本控制：**当前提交即回滚点**，不需要额外备份仪式。
- 非 git 场景：动码前留一个可退回的快照（当前工作区副本或分支），出问题能退回；快照放持久存储，⛔ 临时目录。
- ⛔ 不把「强制打包备份到固定目录」当通用流程——那是特定仓的耦合。

## 四、逐项验证（Y5）

上一项验证不过，不进下一项；不允许「先记着，以后修」。每一项都要能指着同一条用例／命令说：修复前失败、修复后通过。

## 五、交接对接

跨 agent 交接的**格式与模板**归 `handoff` 件；本件只在需要交接时提供调试事实：根因、因果链、证据级、已排除假设、复现方式、未验证部分。交接时不夹带未授权改动（范围锁见正文横切闸）。

**升级清单**（停下升级用户时用，不是跨 agent 交接模板）：把八段汇报裁剪为四项事实＋一项诉求——根因、已排除假设、复现方式、未验证部分，外加「需要用户做什么」（凭据／环境访问／采集件／方案拍板）。⛔ 不在本件另立交接格式。
