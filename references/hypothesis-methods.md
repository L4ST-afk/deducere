# 假设方法卷（循链问展开）

> 配合 `对鸟Deducere` 使用。正文只保留「多条可证伪假设先排序、用户判断降为假设 #1」；本卷给对照方法、合议流程与降级路径。

## 目录

§一 兄弟件对照（G4）｜§二 边界二分（G9）｜§三 何时开合议（G6）｜§四 合议流程与降级（G7）｜§五 第三方库先查文档（G8）｜§六 停挖与重排（G11）

## 一、兄弟件对照（G4）

找一条**最近的正常路径**（同模块能跑的兄弟件、旧版本、另一套配置），逐条列差异。每条差异自带证伪方式：把它改成与正常路径一致，看 bug 是否消失。

- 差异清单只列有代码/配置依据的项；读不到依据的标「未核实」，不进对照。
- 对照结论要能回到 `file:line`；纯「感觉差不多」不算差异。

## 二、边界二分（G9）

跨组件系统先按边界二分，定位哪一层出入现实偏离，再对该层假设：

- 典型链路：CI → 构建 → 签名；客户端 → API → 服务 → DB。
- 先在边界上取证据（请求到没到、响应从哪层出来、数据在哪层变样），把偏离层圈出来，再下沉到层内假设。
- ⛔ 不在边界未清时，直接对最远端组件猜根因。

## 三、何时开合议（G6）

合议是高仪式成本手段，只在非平凡案例启用：

- **不开合议**：G0 快诊；单文件、已有现成红灯命令的简单空值／typo，直接 1–2 条假设推进。
- **开合议**：多因并存、跨模块、回归「莫名出现」；或假设 ≥3 条、各有 `file:line` 证据、预测互斥且等权分不出先后。

## 四、合议流程与降级（G7）

目的是防单链锚定，**不是投票**：

1. 并行各守一条假设，并行度 1–3：每条带可证伪预测＋`file:line` 证据；找不到证据明说，⛔ 编。并行只做只读调查，改码仍串行单点；分支隔离工作树／端口／数据副本／随机种子，结论逐条登记假设、预测、`file:line`、证据级与裁决态（确认／证伪／重排），回填 J9／J14。
2. 交叉质询：对每条假设的证据级与预测回读，丢证据不足的。
3. 回主上下文重排：保留经得起质询的假设进验真问；合并以证据级＋可证伪预测命中为准，⛔ 按票数取人多的那条。

**降级顺序**（子 agent 通道不可用时）：

1. 先试只读子 agent 并行；通道返回不可用标记时，
2. 退化为当前上下文按假设逐条自问自答：每条单独写预测与证据，再统一回读，⛔ 混在一条思路里互相印证。

## 五、第三方库先查文档（G8）

怀疑第三方库行为前，先查**当前版本**文档与变更说明：训练数据可能落后，可能是已知问题或已修问题。

- 有 docs 检索通道：查当前版本文档与 issue。
- 无该通道：降级为核对版本号、变更日志与已知问题列表；⛔ 把「文档说如此」当已核实证据。

## 六、停挖与重排（G11）

探针 3 轮均未证实也未证伪主假设，回循链问带证据重排，不隧道钻第一条（判据 J15）。轮次口径引 T3（已转正、证据级 L0，待 ≥2 次同类实测回调）；「久挖不动就回炉重排」是本件纪律，数字以 T3 为准。
